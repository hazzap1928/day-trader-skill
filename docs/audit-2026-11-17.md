to write this. The only new file is this one. Branch `t212-adapter`, with the uncommitted work of 17 Nov

## 1. Summary in plain English

**Overall health: good code, carrying a lot of dead weight.** The parts that run today (drift, news, the
guard, the holdings record, the daily review, the reports) are careful, well tested and consistent.
All 1,355 tests pass. Almost every function is still called by something. The safety switches that keep
the agent on the demo account all still hold.

The problem is size, not quality. Roughly **40% of the code** exists only to serve day trading, which is
switched off. It cannot simply be deleted yet, because the live parts borrow small pieces from it in a few
places (listed below). Four files have grown far too big to read in one go, and CLAUDE.md is long enough
that every new Claude session spends a large part of its reading on things that no longer run.

**The top 5 issues**

1. **Restoring an old config would switch day trading back on.** The "day trading off" switch was only
   added today. If it is missing, the code treats day trading as ON. 16 of the 17 config backups do not
   have the switch, and the newest backup has it set to ON. Restoring any of them by mistake would restart
   the opening-range scanner on its next cycle.
2. **A share with no strategy label is still treated as a day trade.** It gets the trailing stop and is
   sold at 15:50 New York. A buy placed by hand with `t212.py place` is labelled "day trade" unless told
   otherwise. With day trading off, nothing should be sold that way; it should be kept and reported.
3. **The live parts lean on the day-trading code in hidden ways.** The tradable universe (used by drift
   and news) borrows its web download and clock helpers from the dormant scanner. The Friday report (which
   carries the drift and news sections) lives inside the dormant `evidence.py`. Every buy, including drift
   and news, goes through helper functions in the old `ticket.py`. These links must be cut before the
   day-trading code can go.
4. **Two background programs can overwrite each other's files.** The phone outbox and the holdings record
   are written by more than one program (the autopilot, the guard, the briefing, the news runs) with no
   lock, the same kind of clash that stopped the guard on 17 Nov. The worst case is a lost phone message or
   a lost holdings change, not a wrong trade.
5. **Your personal email address is in the public history.** 28 commits on the public branch were made
   with a personal Gmail address as the author (before the switch to GitHub's no-reply address on
   11 Nov). No keys, tokens, account numbers or files from `trader/` were ever committed.

**What could be removed:** (the scanner, entry, exit and Time Machine folders are now kept as repurpose
candidates, see the update above) the old ticket chat flow, the
day-trading half of the autopilot, the trailing stop and half-sale, the evidence-mode signal log, the
day-trading limits, the Pelosi tracker, and (your call) Kronos. About 25 of the 50 test files go with them
in whole or in part. Done in the order in section 6, each step is small and can be tested on its own.

**Also worth knowing:** several docs still describe the original "11 skills for day trading" pack
(README.md, the plugin files, most SKILL.md files, METHODOLOGY.md), and one test (`test_repo.py`) actually
insists on that old description, so it has to change before any folder can be deleted.
